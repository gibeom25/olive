OLIVE Code Flow

A frozen 7B VLA, a trainable ~2.16 M z-space head, and one per-timestep core that BC, PPO, and eval each wrap differently. Everything routes through train.py --phase {bc|ppo|all}.

  • trainable — Actor W1/W2, Critic W3/W4, log_std
  • frozen — VLA (7B), basis B, LM head
  • checkpoint / metric produced

1  ·  The per-timestep core

One observation → one 7-DoF action. Reused verbatim by every phase; only the decode mode and how z is drawn change.

2  ·  Three phases wrap the core

Shared setup builds backbone + head once; then one of BC / PPO / eval runs, each producing its own artifact.

3  ·  Module ownership

Imports are one-way: train.py composes everything; leaf modules don't import each other, except evaluate → rollout / libero_env.

4  ·  Deviations & open gaps

Where this departs from the paper

  • z-space policy. Gaussian over the 256-D latent, not the 7-D action — rollout decodes greedily, no gradient through the backbone.
  • BC warm-up added. Last run used bc.targets = critic (Actor BC was a no-op).
  • PPO defaults retuned after KL blew up: entropy_per_dim=True, target_kl=0.05, lr_start=1e-4. Paper values via --ablation paper_ppo.
  • Round-robin cursor persists across PPO iterations so tasks are visited evenly.

Known gaps — next work

  • 1Value targets un-normalized → grad-norm 500–2000 hard-clipped → near-zero effective update. Add running mean/std on returns in ppo_trainer.py.
  • 2Rollout & eval are batch-1, sequential. Vectorize the envs so a 50k-step run is hours, not days.
  • 3Actor BC gradient is tiny — the soft-decode softmax is probably saturating.
  • 4reward.LAMBDA_STEP and ppo.total_steps aren't pinned by the paper.
